Here are some examples:

- When heavily using remote projects (as I do, locating all my "work" projects on my Mac mini), it can be hard to find a specific chat in the mobile application. First of all, opening a project requires four taps: sidebar menu icon, "Explore", "Projects", your project name. But actually, no! If your project is a remote Codex project, it will not show in that list. You have to first click "Codex" in the sidebar menu, then you'll find a list of remote projects.
- In Codex's "projects", you'll also find "cloud" projects, which are projects that don't run on a machine you own. However, you won't find all chats for such project on a single screen. Some chats, started in the "Chat" UI (probably the original ChatGPT interface?) will not show in Codex, while others, started in the "Work" UI (likely the original Codex interface?) will not show on the ChatGPT side. I'd guess this is because ChatGPT and Codex used to be two separate apps, and merging the two apps last summer left some quirks in the UI. For someone who barely used the Codex app before it got folded into ChatGPT, it is really unintuitive.
- Similarly, different types of "chats" are aggregated into a single "Recent" list on the macOS app, some can be moved into projects, others can't (even when the UI offers the option), some chats offer a "delete" option while others can only be archived. This is a bit of a confusing mess to be honest, and I wish it was clearer what I'm dealing with.
- Synchronization between devices is sometimes erratic, and includes the risk of losing some of the exchanges you had. Twice, I've opened a chat from my phone that I had previously started on my laptop, and before noticing that it had not been synced, sent a new message. This simple interaction resulted in ChatGPT "forgetting" about the messages that had happened on my laptop but not synced to my phone. Those messages disappeared from the UI and from the context, with no possibility for me to retrieve them. This is a very impactful bug that I fear to encounter again.
- In the macOS app, clicking the "New chat" icon right next to a remote project's name won't consistently start that chat in the project.
